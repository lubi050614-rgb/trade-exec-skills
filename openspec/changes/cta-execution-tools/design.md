## Context

基线 execution_tools_ai_spec.md 第 15–20 节。股票和 CTA 同仓库、独立领域核心，金额/时间/Schema 基础设施可共享，独立导出时核心随包分发。

## Goals / Non-Goals

目标：24 个真实可调用入口和可恢复模拟闭环；Agent 错用股票权重、跳过开平依赖、使用过期版本、编造成交均明确拒绝。
非目标：生产账户服务、真实交易所规则认证、ClickHouse、自动强平、跨品种组合保证金、公司生产鉴权。

## Decisions

- SQLite BEGIN IMMEDIATE 串行化订单、预留、事件和成交容量；CTA 使用独立表及 FUTURES 资产类别，不将两个 mock 账本伪称统一生产资金账户。
- 持仓以多空/今昨分桶逐笔记录核算基准；首版净目标遇到同时持有多空明确拒绝。
- 显式日历列出 session start/end/trade_date，夜盘归属按区间查询，禁止自然日期加一推断交易日。
- 订单规划持久化并分配计划腿 ID。开仓依赖引用真实计划腿；只在全部平仓成交已记账后允许注册，不信任 Agent 声明依赖已完成。
- 登记和冻结在同一 Atomic 完成。匹配为纯计算；fill-record 根据持久化行情重新计算、校验版本和队列顺序，原子占用容量。
- 成交后依次更新订单、账户、释放。故障点持久化已有步骤并阻塞新交易，可重启按事件恢复。
- equity=已记账余额+未实现盯市盈亏；持仓保证金和订单预留独立记录。费用不重复，释放保证金不记利润。
- 结算以显式 prev_settlement_price/settlement_price 计算剩余仓位新增盯市调整，已实现盈亏与费用不重复入账。版本与输入 hash 固定，跨日今昨迁移仅执行一次。
- 换月计划持久关联旧平/新开腿；进度按已入账成交统计，部分完成显示未衔接敞口。

## Risks / Trade-offs

本地 JSON 行状态适用于仿真，不代表生产高并发架构。mock 股票与 CTA 资金隔离，混合资产实际账户需要后续统一账户服务。原生平台验证器未提供，必须保留该未验证项。

## Validation

测试反手部分成交/依赖、今昨费用/冻结、注册原子性、风险阻塞、日线/分钟线、显式夜盘与假期、双向结算桥接、换月未衔接、四阶段重启恢复、24 个契约与独立导出、股票回归以及官方 OpenSpec strict。
